# Oracles

Test oracles that validate rades signatures against third-party implementations.

## Structure

```
tests/oracles/
├── manifest.json          # Signatures to validate + expected outcomes
├── test-pki/              # Test PKI (generated by generate.sh)
│   ├── generate.sh        # Regenerates the whole PKI and fixtures
│   ├── root-ca/           # Root CA certificate + key
│   ├── intermediate-ca/   # Intermediate CA certificate + key
│   └── signers/           # RSA 3072 and ECDSA P-256 signers (+ PKCS#12)
├── dss/                   # DSS oracle (DSS 6.5.1 via JBang)
│   └── validate.java      # DSS validator script
├── autofirma/             # AutoFirma oracle and fixtures
│   └── generate-fixtures.sh  # Generates CAdES fixtures with test PKI
└── README.md              # This file
```

## Running

```bash
# Run all oracles (requires JBang installed)
just oracles

# Regenerate the test PKI and third-party fixture
bash tests/oracles/test-pki/generate.sh

# Regenerate AutoFirma fixtures
bash tests/oracles/autofirma/generate-fixtures.sh
```

## Maven Central status

**AutoFarma artifacts (`es.gob.afirma:afirma-crypto-*`) are NOT on Maven Central.**

Per issue #8, we checked both:
- `es.gob.afirma:afirma-crypto-*` — not available
- `es.gob.rfirma:rfirma-*` (rFirma reference signer) — not available

When these artifacts become available, the AutoFirma oracle can be completed.
Until then, fixtures are generated with `openssl cms` as placeholders.

## DSS

DSS (Digital Signature Services) from EU Europa is available at:
- Group ID: `eu.europa.ec.joinup.sd-dss`
- Version: 6.5.1 (as specified in the original issue)

The DSS oracle validates signatures through JBang, trusting only the test root CA (offline, no LOTL).

## CI

A separate `oracles` job runs on Linux on every PR (see `.github/workflows/ci.yml`).
